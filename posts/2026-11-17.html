今日實戰主題一：AI 專案憲法工程——用 AGENTS.md / .cursor/rules 終結 AI 失憶

為什麼你每次都要對 AI 重複叮嚀一樣的話？

無論你是用 Cursor、Claude Code、Antigravity 寫程式，還是用專案型工作區整理報告，最令人崩潰的日常莫過於：昨天才剛教過 AI「這個專案用 Tailwind v4、文字一律用繁體中文、測試要先跑哪支腳本」，今天開一個新視窗，AI 又全部忘光光，甚至自作主張安裝不相容套件或覆寫舊設定。

2026 年最成熟的解方不再是「把 1,000 字規範存成記事本每次手動複製貼上」，而是導入「專案憲法工程（Repository-Level AI Rules）」：將規則直接存成專案資料夾內的標準 Markdown 檔案，讓任何 AI Agent 在動手前自動先讀完家規再執行。

💡 一句話痛點破解： 不要只靠大腦記憶或對話框口頭提醒；將「技術棧、常用指令、絕對禁忌（Never-do List）」寫進根目錄 AGENTS.md 並搭配路徑觸發規則，讓每個 AI 助手第一秒上工就成為熟手老同事。

Step-by-step 五步驟落地指南

  • 1
    先寫一份「極簡 30 行憲法」而非萬言書： 只放 AI 猜不到的資訊！包含：專案一句話定位、套件管理器與正確測試指令（如 pnpm test）、核心目錄結構說明。避免把整份開發手冊倒進去，規則超過 300 行會導致模型注意力稀釋。
  • 2
    建立「犯錯免疫機制（Never-Do List）」： 不要一開始就憑空幻想 50 條規定。每當 AI 犯了一個愚蠢錯誤（例如偷用已淘汰的 API、把日期格式寫錯），修完 Bug 後立刻在 AGENTS.md 補上一條負向禁忌：「❌ 嚴禁直接修改 dist/ 產物」，讓它從此記住教訓。
  • 3
    用 Glob 路徑拆分局部規範（按需載入）： 寫後端 API 時才需要知道 SQL 交易鎖怎麼開，寫行銷文案時不需要看資料庫規則。利用 .cursor/rules/*.mdc 的 globs 或子資料夾放置局部 AGENTS.md，達到「只看眼前該看的規矩」。
  • 4
    把「死板格式」交給 Linter，規則檔只留「判斷原則」： 縮排幾格、單引號或雙引號，交給 Prettier / ESLint / Ruff 自動修正最準確且零 Token 成本。你的規則檔應該專注於「為什麼這樣設計」、「異常情況怎麼處理」等高價值語意規範。
  • 5
    納入 Git 版控，讓團隊知識複利滾雪球： 將 AGENTS.md 提交到團隊倉庫。從此任何一位同事用 AI 開發新功能，都能瞬間繼承資深工程師累積下來的最佳實踐與避坑經驗。

今日實戰主題二：模型路由（Model Routing）與「快慢思考」算力調度術

痛點剖析：為什麼用了最貴的旗艦推理模型，卻又慢又容易「想太多」？

這兩年 AI 模型生態已經明確分裂成兩大類：一種是追求極速直覺反應的「非推理快模型（System 1 快思考）」（例如 Gemini Flash、GPT-4o-mini、Claude Haiku），幾乎零等待就開始吐字；另一種是會先在內部進行長思維鏈推演的「深度推理模型（System 2 慢思考）」（具備 Thinking / Reasoning Budget 機制）。

很多使用者不管遇到什麼問題，一律鎖死在最貴、思考最久的旗艦推理模型上。結果只是請它把一封英文信翻成中文或整理表格，它卻在後台「沉思 18 秒」才回答，不僅白白燒掉數倍成本，還常因為過度推理（Overthinking）而把簡單任務改寫得過於複雜！

🚨 痛點破解關鍵： 頂尖工作流不是「找一個萬能最貴模型」，而是像醫院急診檢傷一樣建立「智慧模型路由（Model Routing）」：80% 高頻常規任務交給快思考模型秒殺；只有 20% 跨系統架構、深度邏輯除錯與策略權衡，才調度慢思考模型深挖！

「快思考」vs「慢思考」模型選型與 Prompt 心法對照表

比較維度 ⚡ 快思考模型（System 1） 🧠 慢思考推理模型（System 2）
運作原理 單次前向直覺生成，幾乎不額外消耗隱藏推理 Token 輸出前先在內部「草稿區」自我詰問、反推與驗證多條路徑
延遲與成本特徵 首字延遲極低（< 1 秒），API 單價通常僅為旗艦模型的 1/10 ～ 1/30 需等待數秒至數十秒思考時間，且隱藏 Thinking Token 亦計費
最適合實戰場景 會議逐字稿摘要、中英翻譯、JSON 抽取、客服分類、局部程式碼補全 跨模組 Bug 根因分析、架構選型權衡、複雜法務/財務推算、多步規劃
Prompt 撰寫心法 指令要具體：給出明確步驟、Few-Shot 範例與嚴格輸出範本 Prompt 要做減法！寫清「目標、脈絡、驗收標準」即可，別強迫它照你的步驟想
最常見反模式（誤區） 要求它「一次做 5 層深度推理」，卻沒給範例導致直接產生幻覺 把「整理通訊錄 CSV」這種瑣事丟給它，結果等半天還幫你多加不需要的欄位
💡 2026 進階實戰技巧 — Thinking Budget（思考預算）調節閥： 現代主流模型 API（如 Gemini 系列的 Thinking Level、OpenAI 的 Reasoning Effort、Claude 的 Extended Thinking Budget）都允許在請求中指定 low / medium / high。寫日常小腳本調 low，做系統上線前安全審計調 high，同一支模型就能自由切換腦力檔位！

Step-by-step 四步驟打造個人與團隊模型調度策略

  • 1
    盤點你的日常任務「80 / 20 象限」： 打開你過去一週的 AI 對話紀錄，統計一下有幾成是「翻譯、改寫信件、查語法、摘要文章」？先把這 80% 全部預設切換到高速輕量模型，馬上就能體會秒回的爽感。
  • 2
    對推理模型練習「目標導向式提問」： 使用慢思考模型時，刪掉過去習慣寫的「請先分析 A，再列出 B，最後推導 C...」等微管理指令。改為直接交代：「這是系統目前的架構限制與錯誤 Log，請找出真正的根本原因，並提出改動幅度最小的修復方案。」
  • 3
    建立「先快後慢」的兩段式接力工作流： 處理複雜任務時，先用慢思考模型花 30 秒規劃藍圖與介面規格（Planner）；規格拍板後，切換成快思考模型批量生成重複性高的頁面、測試資料或翻譯內容（Worker），效率直接翻倍。
  • 4
    自動化腳本導入「級聯升級（Cascading）」保險絲： 若你有寫 Python / n8n 批次處理資料，透過 LiteLLM 或 OpenRouter 設定：先呼叫低成本快模型輸出 JSON；只有當程式檢查格式失敗或信心分數偏低時，才自動 Fallback 重試高階推理模型，輕鬆省下 70% API 預算！

今日 5 分鐘實戰練習（Micro-Action）：一鍵生成你的專屬 AGENTS.md 專案憲法

立刻替你手邊最常用的專案（或個人工作區）立好家規

不用從零苦惱怎麼寫規範！複製下方 Prompt，貼進你的 Cursor / Claude Code / ChatGPT / Gemini 對話框，並簡單填入你的專案或日常工作背景，AI 就會替你生成一份精煉、不廢話、含紅線禁忌與模型調度建議的標準 AGENTS.md 憲法檔： 

請扮演一位資深的「AI 系統架構師與團隊工作流顧問」，協助我為目前的專案／工作區撰寫一份可直接落地的根目錄規範檔 `AGENTS.md`。

【我的專案／工作區基本資訊】
- 專案名稱與目標：[例如：電商後台管理系統 / 個人每日自動化爬蟲與週報生成器]
- 核心技術棧或常用工具：[例如：Next.js 15 + TypeScript + Tailwind v4 / Python 3.12 + Playwright]
- 常用執行與測試指令：[例如：pnpm dev / pytest -q]
- 過去 AI 最常犯的 3 個錯誤（痛點）：
  1. [例如：常把輸出或註解寫成簡體中文，我一律要求繁體中文]
  2. [例如：喜歡自己安裝新套件或大幅重構我沒要求改的舊檔案]
  3. [例如：常忘記先跑完測試確認通過就宣稱任務完成]

【請依以下結構輸出精煉的 AGENTS.md（總長度嚴格控制在 120 行以內）】
1. **專案一句話定位與目錄地圖**：只列出最重要的 3~5 個關鍵資料夾用途。
2. **標準作業指令（Build / Test / Lint）**：讓 Agent 知道修改後必須執行哪條指令自我驗證。
3. **溝通與產出規範**：語言、格式、修改範圍限制（最小變動原則）。
4. **絕對禁忌紅線（Never-Do List）**：用條列式明確禁止上述痛點與安全風險（如禁止寫死 API Key）。
5. **模型路由建議（Model Routing Hints）**：區分哪些子任務適合用「快思考模型」處理，哪些必須切換到「深度推理模型」謹慎評估。

【輸出要求】
- 使用繁體中文，語氣直接明確（多用「必須 / 禁止」，少用「盡量 / 建議」）。
- 直接輸出完整 Markdown 程式碼區塊，方便我一鍵存檔為 `AGENTS.md`。

今日實戰主題一：別再讓 AI 一條路走到黑！Tree of Thoughts（思維樹多路徑推演術）

為什麼「請一步步思考（CoT）」還是常常產出平庸方案？

大家已經很熟悉用「請一步步思考（Chain of Thought, CoT）」來讓 AI 講出推論過程。但 CoT 有個先天限制：它是「單線一條龍」的文字接龍。只要 AI 在第 1 句選了一個最常見、最保守的假設（例如「提高曝光靠下廣告」），接下來的 800 字都會順著這條平庸路線越寫越自洽，根本不會回頭思考「有沒有完全不同的高槓桿打法？」。

2026 年在策略企劃、架構選型與商業決策中最強的進階技法，叫做「思維樹推演（Tree of Thoughts, ToT）」——強迫 AI 在動筆展開細節前，先長出 3 條彼此互斥的策略分枝，用量化權重「修剪掉爛枝」，最後把冠軍路線與亞軍亮點合併成終極方案。

💡 一句話痛點破解： 不要讓 AI「想到哪寫到哪」，而是要求它先交出 「3 條截然不同的路線草圖 ➔ 客觀打分淘汰 1 條 ➔ 吸收亞軍優點組裝最終版」，用 1 次對話換來 3 位顧問腦力激盪的品質。 
flowchart LR
    Q["🎯 複雜決策或企劃題目"] --> B1["🌿 分枝 A：低成本游擊路線\n(3行核心假設與限制)"]
    Q --> B2["🌿 分枝 B：高價值精品路線\n(3行核心假設與限制)"]
    Q --> B3["🌿 分枝 C：工具生態借力路線\n(3行核心假設與限制)"]
    B1 --> Eval["⚖️ 權重剪枝矩陣\n可行性 × 成本 × 風險 × 見效速度"]
    B2 --> Eval
    B3 --> Eval
    Eval -- "淘汰最低分路線" --> Prune["✂️ 明確說明放棄原因"]
    Eval -- "保留冠軍 + 借鏡亞軍亮點" --> Final["🏆 混合強化版最終執行方案"]
圖 1：Tree of Thoughts（思維樹）「發散分枝 ➔ 權重剪枝 ➔ 融合收斂」三段式推演架構
推演模式 思考路線 常見盲點 最適合使用的場景
直接問答 (Zero-Shot) 直覺跳到結論 容易遺漏前置條件與風險 查定義、單純翻譯、格式轉換
思維鏈 (CoT) 單一線性展開 (A1 ➔ A2 ➔ A3) 開頭假設若普通，整篇都在合理化平庸解法 數學計算、已知標準流程的步驟拆解
思維樹 (ToT) 多路平行探索 + 評分剪枝 + 融合 花費較多輸出 Token（建議用輕量綱要分枝） 產品企劃、系統技術選型、職涯/商業難題決策
  • 1
    強制互斥發散（Diverge with Constraints）： 在指令中明確規定「必須提出 3 個邏輯完全不同的解法」，例如限制「一個靠零預算人工流程、一個靠現成 SaaS 串接、一個靠寫小程式自動化」，避免 AI 產出換湯不換藥的三個複製人選項。
  • 2
    輕量綱要＋量化剪枝（Score & Prune）： 要求每個分枝先只寫 80 字摘要與「最大致命傷」，並依你設定的 4 項權重（例如：1週內上線 35%、維護成本 25%、擴充性 20%、風險可控度 20%）列表打分，主動淘汰最後一名。
  • 3
    跨枝嫁接與深度展開（Synthesize & Deepen）： 挑選第一名為主骨架，同時要求 AI「從第二名路線偷師一個關鍵優勢嫁接進來」，再展開具體的 Step-by-step 執行清單與驗收指標。

今日實戰主題二：15 分鐘摸透萬行陌生專案！AI 程式碼考古學（Repomix ＋ 影響半徑圖譜）

為什麼接手舊專案或開源碼時，叫 AI 直接「幫我加個功能」最容易翻車？

無論你是剛從 GitHub 下載了一個超酷的開源工具想魔改，還是打開自己三個月前寫到一半的專案，最致命的錯誤就是「只丟單一檔案給 AI，叫它馬上改程式碼」。因為 AI 看不到全域的呼叫關係與資料流向，它往往會忘記改到隱藏在另一個資料夾的設定檔，甚至好心幫你重寫了一個專案裡早就存在的共用函式。

高手接手陌生專案時，會先執行一套「AI 程式碼考古學（Codebase Archaeology）」：先把整座倉庫濃縮成乾淨的上下文包裹，讓 AI 先畫出「入口點 ➔ 核心資料流 ➔ 影響半徑雷達圖」，完全看懂地圖後才動第一行程式碼。

💡 一句話痛點破解： 接手陌生專案的前 15 分鐘「只讀不寫（Read-Only Mapping）」！先用 Repomix 把乾淨目錄打包餵給長上下文 AI 畫出系統地圖與修改影響半徑，準確率遠勝盲目開改。 
flowchart TD
    Repo["📦 陌生專案資料夾\n(數十個檔案與巢狀目錄)"] --> Pack["🗜️ 步驟一：全景打包過濾\nRepomix / gitingest\n(排除 node_modules 與二進位雜檔)"]
    Pack --> Map["🗺️ 步驟二：畫出結構雙圖\n入口點 Entry Point + 核心資料流向"]

    Blast --> Safe{"🛡️ 人類確認路線圖\n是否有遺漏的相依模組？"}

Repomix
(npx repomix)		 自動讀取 .gitignore，將整個專案壓縮為單一 Markdown/XML 檔，並統計 Token 數 把整棟大樓的藍圖與水電管線裝訂成一本「精華目錄冊」 本機有程式碼資料夾，想一次丟給 Gemini / Claude 看懂全貌
Gitingest
(網址把 github 改 gitingest)		 免安裝工具，貼上公開 GitHub Repo 網址即秒轉純文字結構包裹 線上版「開源專案 X 光機」 快速研究網路上的開源專案、學習別人的實作架構
CLI Agent 只讀探勘
(Claude Code / Gemini CLI)		 直接用終端機指令搜尋符號引用、追蹤 Call Graph 與歷史 Git Commit 派一位資深偵探直接進現場調閱監視器與翻找線索 超大型專案（超過數十萬行），無法一次塞進單一對話視窗時
  • 1
    淨空打包（Context Packing）： 在專案根目錄執行 npx repomix --style markdown（或對公開 GitHub 專案直接打開 gitingest.com），系統會自動濾掉 node_modules、圖片與暫存檔，產出一份帶目錄樹的純文字檔案，並檢查總 Token 是否落在模型甜蜜點（例如 10 萬 Token 內）。
  • 2
    先問「誰是起點、資料怎麼走」： 把打包檔餵給 AI，禁止它改程式，只問三個問題：「1. 使用者觸發動作後，請求經過哪幾個檔案？ 2. 全域設定與環境變數都在哪裡讀取？ 3. 哪三個檔案是整個專案的心臟？」並要求它用 Mermaid 畫出來。
  • 3
    動刀前先算「影響半徑（Blast Radius）」： 鎖定你要改的功能後，請 AI 列出所有呼叫該函式的上游檔案、共用的資料型別，以及現有的相關測試檔，確認「牽一髮會動哪幾身」之後，再開始撰寫修改程式。

今日 5 分鐘實戰練習（Micro-Action）：ToT 思維樹決策 ＆ 專案影響半徑萬用模板

一鍵啟動「三路線推演 ＋ 量化剪枝」高勝率決策腦

今天不論你要評估一個新點子、決定系統架構，還是煩惱某個職場企劃該選哪種打法，請複製下方這套「Tree of Thoughts（思維樹）三路線評估模板」，直接貼給 AI 試跑一次，體會「多路徑比較」與「單線盲猜」的巨大差距： 

【任務目標】
請針對以下難題，運用「Tree of Thoughts（思維樹多路徑推演）」模式協助我找出最優解法，先不要急著給單一答案：
- 我的題目／情境：[填入你的決策難題，例如：我想做一個自動化每週帳務整理工具 / 我們團隊想導入 AI 客服]
- 我的資源與限制：[例如：只有週末 4 小時可開發 / 預算零元 / 不希望客戶資料外洩]

【第一步：發散 3 條互斥策略分枝】
請提出 3 條「思考維度完全不同」的路線（例如：路線 A 極簡手工替代、路線 B 現成工具串接、路線 C 輕量程式自動化）。
每條路線限用 4 行交代：核心作法、所需工具、最大前提假設、一個潛在致命傷。

【第二步：權重評分與剪枝】
請用 Markdown 表格，依以下權重對 3 條路線進行 1~10 分評分：
- 落地速度 (35%)｜長期維護成本 (25%)｜效果上限 (25%)｜風險可控度 (15%)
計算加權總分後，明確說明「淘汰哪一條路線以及為何淘汰」。

【第三步：跨枝嫁接與行動清單】
選出最高分路線作為主軸，並從第二名路線中「借鑑一個優點」進行混合強化，最後給出明天就能執行的 3 個 Step-by-step 落地步驟。

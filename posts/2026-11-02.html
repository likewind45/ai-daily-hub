今日實戰主題一：告別長篇大論！用 XML 結構化標籤精準控制注意力

當你的指令超過 200 字，AI 為什麼開始「選擇性失明」？

當我們把背景資料、參考範例、禁止事項和任務要求全部混在同一個段落裡時，大型語言模型（LLM）的注意力機制（Attention）很容易把「參考文章裡的句子」誤認為「你的指令」。使用類 XML 標籤（如 <context>、<constraints>）或是清晰的 Markdown 區塊，能幫模型畫出絕對分明的語意邊界。

💡 一句話痛點破解： 不要把指令寫成一篇散文；把 Prompt 當成「表單」來設計，結構越清晰，AI 遵循複雜規則的準確率越高。 
flowchart LR
    subgraph Bad["❌ 傳統糊成一團的 Prompt"]
      B1["背景 + 範例 + 規則 + 任務
全部塞在同一段文字"] --> B2["😵 模型注意力混淆
漏掉限制條件、模仿錯語氣"]
    end
    subgraph Good["✅ 結構化分層 Prompt 架構"]
      G1["<role> 角色與專業視角"] --> G2["<context> 業務背景與受眾"]
      G2 --> G3["<examples> 1~2 個黃金範例 (Few-Shot)"]
      G3 --> G4["<constraints> 絕對禁止詞庫與格式要求"]
    end
    Good --> Result["🎯 精準鎖定風格與邊界
一次產出可商用等級成果"]

<context> 交代真實業務情境與讀者是誰 「這份報告要給完全不懂技術的傳產董事會看，他們只關心投資回收期（ROI）與風險。」
<examples> 提供 Few-Shot 少樣本示範（最有效！） 貼入一段你過去寫得最滿意的 150 字段落，告訴它：「請嚴格模仿這個節奏與用詞密度。」
<negative_rules> 封殺 AI 罐頭腔調與常見廢話 「禁止使用『在當今快節奏的時代』、『總而言之』、『把雙刃劍』等空洞套話；每點必須有具體動詞或數字。」

今日實戰主題二：單輪對話內的「自我反思迴圈（Self-Reflection Prompting）」

不用分三次罵它！讓 AI 在同一個回覆裡「自己審稿、自己重寫」

研究顯示，如果直接請 AI 寫出最終答案，它會順著機率最高的平庸詞彙一路生成下去。但如果你強制它在輸出最終答案前，先經過「初稿生成 ➡️ 嚴格評審挑刺 ➡️ 修正定稿」的三段式內部迴圈，內容深度會出現肉眼可見的躍升。 

flowchart TD
    Task["📝 輸入任務需求"] --> Step1["第一階段：快速初稿 (Draft v1)
先依直覺產出完整內容框架"]
    Step1 --> Step2["第二階段：毒舌總編審查 (Critique)
強制抓出初稿中 3 個最空泛、缺乏數據或邏輯跳躍的弱點"]
    Step2 --> Step3["第三階段：終極精修版 (Final Polish)
針對上述 3 個弱點逐一補強並重寫為最終交付物"]
    Step3 --> Done["✨ 使用者直接獲得經過一輪嚴格打磨的高品質定稿"]

今日 5 分鐘實戰練習（Micro-Action）：三段式自我反思（Draft-Critique-Refine）萬用模板

下次寫重要信件、企劃案或技術文件時，直接套用這個「自帶總編審稿」的神級模板

複製下方 Prompt，把 [任務內容] 換成你手頭正在處理的工作：

<task>
請幫我撰寫：[填入你的任務，例如：一封向客戶說明系統升級導致短暫停機的公告信 / 一份新產品上市的 3 個月推廣企劃]
</task>

<context>
- 目標受眾：[填入受眾，例如：付費企業客戶的 IT 主管]
- 核心目標：[填入目標，例如：安撫情緒、清楚交代時間點、展現專業補償方案]
</context>

<negative_rules>
- 禁止使用任何翻譯腔或 AI 罐頭開場白（如「在數位化時代...」）。
- 段落必須精簡，多用列點與表格呈現關鍵時程或數據。
</negative_rules>

<workflow>
請嚴格按照以下三個階段在本次回覆中依序輸出：
【階段一：初稿 V1】先快速寫出第一版內容。
【階段二：毒舌審查員挑刺】請切換視角扮演最挑剔的目標受眾，一針見血地指出【初稿 V1】中哪 3 個地方太官腔、不夠具體、或可能引發誤解。
【階段三：終極完美版 V2】根據階段二的 3 點批評，徹底重寫並補強細節，給出我可以直接複製發送的最終版本。
</workflow>

什麼是 GGUF 量化？記憶體速算公式一分鐘搞懂

大模型原始出廠權重通常是 16-bit 浮點數（FP16），代表每個參數需要 2 個 Bytes（16 位元）來儲存。例如一個 80 億參數（8B）的模型，光是把權重載入記憶體就需要 8 × 2 = 16 GB，還不包含上下文運算空間，一般電腦直接記憶體溢出（OOM）。

GGUF（GPT-Generated Unified Format）量化技術，是將 16-bit 浮點數權重透過分組縮放壓縮為 4-bit 整數（Q4_K_M）。相當於把原本需要 16 個刻度的精細尺子，優化為 4 位元動態區間，模型體積直接縮減 72%，而綜合基準評測（MMLU）準確率損耗僅在 0.8%~1.2% 之間，人眼幾乎無法察覺差異！

📐 本機記憶體需求速算黃金公式：
所需 RAM/VRAM (GB) ≈ [ 模型參數量 (B) × 量化位元數 (bits) ÷ 8 ] × 1.25 (系統緩衝) ＋ 上下文快取 (約 1.5~2 GB)

• 8B 模型 Q4 量化（如 Llama 3.3 8B / Qwen 2.5 7B）： (8 × 4 ÷ 8) × 1.25 + 1.5 ≈ 6.5 GB ➡️ 16GB RAM 即可絲滑順跑！
• 14B 模型 Q4 量化（如 Qwen 2.5 14B）： (14 × 4 ÷ 8) × 1.25 + 2.0 ≈ 10.7 GB ➡️ 24GB / 32GB 記憶體可順跑！
• 32B 模型 Q4 量化（如 Qwen 2.5 32B）： (32 × 4 ÷ 8) × 1.25 + 3.0 ≈ 23.0 GB ➡️ MacBook 36GB/64GB 或雙顯卡工作站首選！

告別冰冷黑底命令列！給本機 AI 一個現代化優雅圖形介面

❌ 終端機對話的實務缺陷：Ollama 預設的 CLI 視窗雖然輕快，但無法保存多重主題的歷史紀錄對話串、無法拖曳上傳 50 頁 PDF 或 Excel 進行即時分析、不支援 Markdown 程式碼高亮排版，更無法為團隊同仁設定權限分工。

Open WebUI（原名 Ollama WebUI）是目前 GitHub 上超過 60,000+ Stars、最炙手可熱的開源 AI 圖形介面。它不僅具備極致仿 ChatGPT 的流暢操作體驗，更原生支援：

  • 📁 完全離線的本機文檔 RAG：將機密 PDF/Word 拖進輸入框，自動在本地切塊並建立向量索引，零外傳進行精準問答。
  • ⚖️ 雙模型並排盲測（Arena Mode）：同一句 Prompt 同步送給 qwen2.5:7b 與 llama3.3:8b，並列比較生成品質與回應速度。
  • 🗣️ 本機語音辨識（Whisper 本地端整合）：用語音直接與本機 AI 交談，語音資料完全不離開筆電。
  • 🔑 完全相容 OpenAI API 規範：支援反向代理，可把本機 Ollama 封裝為標準 API Key，直接串接 Cursor、VS Code 或 Obsidian。

Open WebUI 落地三部曲：一行 Docker 搞定所有配置

  • 1
    透過 Docker 一行指令啟動 Open WebUI：
    只要本機已安裝 Docker Desktop，在終端機貼上下方指令，即可自動下載容器並連結到本機已運行的 Ollama： 
    docker run -d -p 3000:8080 \
  --add-host=host.docker.internal:host-gateway \
  -v open-webui:/app/backend/data \
  --name open-webui \
  --restart always \
  ghcr.io/open-webui/open-webui:main

    📌 提示：啟動後打開瀏覽器訪問 http://localhost:3000，第一個註冊的帳號即為管理員（Admin），所有資料均持久化儲存於本機 open-webui Volume。

  • 2
    配置完全離線的本機 RAG 向量知識庫：
    進入 Open WebUI 的「管理員面板」➡️「文件 (Documents)」設定：
    • 將 Embedding 模型引擎選為 Ollama，並在 Ollama 下載 ollama run bge-m3（目前開源最強中文/跨語言 Embedding 模型）。
    • 從此只要在對話視窗點擊 「📎 附加檔案」，上傳公司的《內部請假規範.pdf》或《供應商合約.docx》，系統就會在本地端自動切塊、向量化並存入本機 Chroma 向量庫，任何查詢都百分之百在內網完成！
  • 3
    無縫串接常用開發工具（Cursor / VS Code / Obsidian）：
    進入「個人設定」➡️「帳號」➡️ 點擊 產生 API Key。 現在你的本機已經具備了一套標準 OpenAI 規格的伺服器！例如在 Cursor 的 OpenAI API Key 填入產生的金鑰，並將 Base URL 設為 http://localhost:3000/api，就能免費、無限制、無延遲地讓本地模型協助你撰寫內部敏感軟體專案。

何時該用雲端？何時必須切換至本地端？

「本地端 AI 是否能全面取代雲端大模型？」客觀來說，目前 70B+ 的雲端旗艦（如 Claude 3.5 Sonnet 或 GPT-4o）在超長多跳躍程式重構、前沿數學推理、複雜 Agent 工具鏈上仍保持領先。然而，在日常 80% 的摘要、改寫、特定領域審查與機密數據處理上，本機模型已經完全能夠勝任，且具備雲端無法比擬的零成本與隱私優勢。

評估維度 ☁️ 雲端旗艦大模型 (Claude 3.5 / GPT-4o) 💻 本機量化開源模型 (Qwen 2.5 / Llama 3.3) 🎯 實戰決策建議
隱私與合規安全 資料須經網際網路傳送至第三方伺服器；有合約與企業審計疑慮 100% 實體隔離 (Air-Gapped)，資料永不離開硬碟 機密合約、內部代碼、財務個資強制選用本機端
使用成本與費用 採 Token 計費制，百萬 Tokens 累積成本高昂 0 元 API 費用，硬體購置後無限次調用 批次大量清洗文本、每日內部監控首選本機
網路依賴性 必須處於高速連線狀態，斷網即停擺 完全離線可用，飛機、山區、保密內網暢行無阻 經常出差或在高資安封閉網路環境必備本機
複雜推理與編程上限 極強，百萬級 Context，複雜演算法與架構能力拔尖 8B~14B 模型在常規任務優秀，但超複雜邏輯偶有幻覺 前沿重大決策或全端系統架構設計可交給雲端
推論速度與延遲 受伺服器尖峰負載與網路排隊影響，偶有卡頓 穩定 30~50 tokens/sec，隨叫隨到零排隊延遲 追求極致即時回應與流暢體驗選用本機
客製化與微調彈性 僅能透過 Prompt 或平台封閉式 Fine-tuning，權重不可控 完全可控，支援 LoRA 微調、自訂 Modelfile 系統層參數 打造企業專屬領域分身或特用模型選用本機

今日 5 分鐘實戰練習（Micro-Action）

【本機專用】商業合約高風險條款審查 ＆ 個資去識別化（Local Redaction）Prompt

這段 Prompt 是專門為 qwen2.5:7b 或 llama3.3:8b 本機模型精心優化的結構化提示詞。你可以直接將它設定為 Open WebUI 的專屬 System Prompt，或貼到對話框中。它能零資料外洩地替你標記出隱藏的法律責任地雷，並將所有敏感個資替換為匿名代號： 

# Role: 嚴謹客觀的企業本機資深法務審查專家

## Context & Security Constraint
你正在執行【完全本機離線環境下的合約風險評估】。你的首要任務是保護企業商業利益，並執行嚴格的隱私資料去識別化（Data De-identification）。

## Task 1：機密個資與商業數字去識別化（Redaction）
在分析文檔時，若偵測到以下資訊，請在輸出報告中強制採用標準代號遮蔽：
- 自然人人名 ➡️ 替換為 `[PERSON_A]`、`[PERSON_B]`
- 公司法人名稱 ➡️ 替換為 `[PARTY_ALPHA]`、`[PARTY_BETA]`
- 具體金錢數字與百分比 ➡️ 替換為 `[AMOUNT_X]`、`[RATIO_Y]`
- 聯絡方式（電話/統編/地址/Email） ➡️ 替換為 `[CONTACT_INFO]`

## Task 2：合約高危漏洞與霸王條款深度審查
請從以下四個維度逐條審核輸入的合約條文：
1. 【無限責任與賠償陷阱】：是否存在「賠償責任無上限（No Cap of Liability）」或連帶間接損失（Consequential Damages）條款？
2. 【智慧財產權（IPR）歸屬】：委託開發標的之著作財產權與衍生專利是否被惡意掠奪或永久無償授權？

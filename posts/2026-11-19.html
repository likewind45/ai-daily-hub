今日實戰主題一：別再叫 AI「用心算」！沙盒程式碼分析 ＆ Text-to-SQL 零幻覺數據實戰

為什麼問 AI「這張表總金額多少？」經常算錯，甚至每次問答案都不一樣？

很多使用者習慣把幾百行的 CSV 貼進聊天框，直接問 AI：「幫我算出各部門的平均客單價與前三名」。但大型語言模型（LLM）的本質是「下一個文字的機率預測器」，而不是計算機。當它直接「用眼睛看數字並用嘴巴吐出結果」時，只要數字超過幾十筆，注意力就會稀釋，進而出現漏行、四捨五入憑感覺、甚至直接編造一個「看起來很合理」的總金額。

在 AI 工程領域，破解這道死結的標準解法叫做程式輔助語言模型（PAL, Program-Aided Language Models），也就是我們熟悉的Code Interpreter（Python 分析沙盒）與 Text-to-SQL（自然語言轉查詢語法）。核心哲學只有一句：AI 不負責算數，AI 只負責「寫出正確的計算指令」，交給 Python 或資料庫引擎算出 100% 精確答案後，再由 AI 負責寫成人話解讀！

💡 一句話痛點破解： 把計算交給程式引擎，把解讀交給語言模型！永遠要求 AI「先在沙盒用 Python（Pandas / DuckDB）或唯讀 SQL 跑出實際統計表，附上執行程式碼與真實結果，禁止心算推測」。

💡 非工程師也能立刻用的神器組合：
• 雲端免安裝首選： 把 Excel / CSV 直接上傳到 ChatGPT（開啟數據分析） 或 Claude（開啟 Analysis Tool），並在指令最後加上一句「請務必執行程式碼計算，不要用文字估算」。
• 本機隱私大容量首選： 把機密報表放在自己電腦，用開源單檔工具 DuckDB 搭配本機 AI 寫 SQL 查詢，不用把整份客戶名單上傳到雲端也能秒查百萬列資料！

Step-by-step 四步驟打造「可稽核、零估算」AI 數據分析流

  • 1
    先餵「資料字典（Data Dictionary）」，再問問題： 上傳表格後，第一句先別急著叫它做圖表，先告訴它關鍵業務定義（例如：「status = 'completed' 才算成交；amount 欄位單位是台幣未稅」），讓 AI 先印出欄位型別與缺失值檢查報告。
  • 2
    強制「先算總量基線（Baseline Check）」： 要求 AI 先用程式算出「總筆數、日期區間、總金額」，並與你手邊 Excel 狀態列看到的數字核對一次。只要基線對不上，後面所有切片分析都先暫停，立刻找出少讀了哪個工作表或編碼格式（UTF-8 / Big5）。
  • 3
    開啟「Show Code 透明稽核模式」： 永遠要求 AI 列出它實際執行的 Python 或 SQL 語法（例如 WHERE created_at >= '2026-10-01'）。就算你不精通程式，也能一眼看懂篩選條件有沒有寫反或漏掉特定分類。
  • 4
    把可重複使用的分析腳本存成「一鍵週報模板」： 一旦驗證這段 Python 或 SQL 邏輯完全正確，請 AI 幫你把整段腳本打包留存。下週只要把新檔案丟進去跑同一段確定性程式碼，連 AI 都不用重算一次，又快又零誤差！

今日實戰主題二：終結「長對話失智與半途斷線」！Plan-and-Execute ＆ 進度交接檔實戰術

為什麼同一個 AI 對話聊太久，表現會呈現斷崖式下滑？

當你要 AI 處理一個大工程——例如「把 12 份會議錄音逐字稿整理成季度白皮書」、「把整個舊網站的 10 個頁面重構為響應式版面」，或「對 20 家競品逐一做調研彙整」——很多人會直接開一個對話視窗從頭做到尾。但實測常會發現：聊到第 10～15 輪時，AI 開始出現上下文腐化（Context Rot）：前面說好不能改的格式被改掉了、第 7 項任務被悄悄跳過、回覆越來越敷衍，最後甚至因為達到對話長度上限或網路斷線而前功盡棄。

頂尖 AI Agent 工作流（如 Claude Code、Manus、LangGraph 的 Deep Agents）之所以能連續穩定工作數小時不走鐘，靠的不是把記憶塞進同一個大腦，而是「規劃與執行分離（Plan-and-Execute）」＋「外部進度檢查點（External Checkpoint / PROGRESS.md）」：每次只讓「乾淨新對話」專心做完清單上的 1 個小步驟，做完就把成果與交接筆記寫進外部檔案，然後果斷換下一個新視窗接力！

💡 一句話痛點破解： 不要把所有任務歷史都背在對話紀錄裡負重前行！把「大腦記憶」外掛成一份人機共讀的 PROGRESS.md 任務看板，讓每個子任務都在全新、零干擾的上下文視窗裡滿血執行。

📌 一份高效率「交接檔（PROGRESS.md）」只需要這 4 個欄位：
1. 全域不動搖約定（Invariants）： 最多 5 條鐵律（例如：用繁體中文、變數命名規則、禁止更動某資料夾）。
2. 里程碑清單（Checklist）： 用 - [x] 與 - [ ] 標註進度。
3. 已拍板決策（Decisions Log）： 已經決定好不再反覆討論的選項。
4. 給下一棒的交接便條（Next Handoff Note）： 下一位新開視窗的 AI 打開後第一秒該讀哪個檔、接著做哪一件事。

Step-by-step 四步驟落地「長任務接力工作法」

  • 1
    第一對話只做「總規劃師」，絕不急著動手： 開啟第一個對話，請 AI 先把你的大需求拆成 4～8 個「每個能在 10 分鐘內獨立驗證」的小任務（Milestones），並要求它直接輸出成一份 Markdown 格式的 PROGRESS.md 計畫書。
  • 2
    人類花 1 分鐘審核計畫書順序： 檢查有沒有漏掉重要前置條件、順序對不對。修改幾行清單文字的成本極低，卻能省下後面重做 2 小時的冤枉路。
  • 3
    「一項里程碑，一個乾淨新視窗」接力執行： 如果是寫文章或分析（使用 ChatGPT / Claude 網頁版），把 PROGRESS.md 貼進新對話，下令：「請只執行清單中下一個未完成的 [ ] 任務，完成後輸出更新版的 PROGRESS.md」；如果用 Cursor / Claude Code，直接開新 Session 指向同一個檔案即可。
  • 4
    收尾前加上「跨棒一致性總檢（Final Consistency Pass）」： 當清單全部變成 [x] 時，最後開一個「總編審視窗」，只把各步驟產出的最終成品（不含中間試錯過程）餵給 AI，檢查前後文風格、名詞翻譯與數據引用是否前後一致，完美交付！

二選一立刻上手：把「試算表丟進沙盒精算」或把「大專案拆成接力看板」

今天挑一個你手邊的真實需求試試看！複製下方這組「沙盒算數稽核 ＋ 長任務規劃交接」雙模式 Prompt 模板（依需要保留模式 A 或模式 B），直接貼進你的 AI 工具實測： 

【任務模式選擇】（請依實際需求保留「模式 A」或「模式 B」）

=== 模式 A：零幻覺數據分析（強制沙盒寫碼／SQL，禁止口算）===
請扮演「資深資料分析師」，針對我提供的檔案／資料表執行分析。為確保 100% 數值準確，請嚴格遵守以下鐵律：
1. 【禁止心算】所有加總、平均、排序與佔比計算，必須實際撰寫 Python（Pandas / DuckDB）或唯讀 SQL 程式碼並在沙盒中執行取得真實結果，嚴禁憑文字估算。
2. 【基線對帳】第一步請先列出「總筆數、日期範圍、關鍵數值欄位總和」與缺失值狀況，讓我與原始資料核對。
3. 【透明稽核】回覆每個洞察結論時，請附上對應的篩選邏輯或核心查詢語法，並以繁體中文 Markdown 表格整理前 5 名與異常項目。
4. 【我的分析問題】：[填入你想問的 2～3 個業務問題，例如：各月份退貨率變化、哪個通路毛利最高]

=== 模式 B：Plan-and-Execute 長任務規劃與交接檔生成 ===
請扮演「資深專案架構師」，我們要完成一個較大的多步驟任務：
- 最終目標：[填入你的大型任務，例如：將 5 份產品文件整理成客戶導入手冊 / 開發一個個人記帳網頁]
- 已知條件與限制：[例如：使用繁體中文、輸出 Markdown、風格需淺顯易懂]

請先「不要急著開始寫最終成品」，只幫我完成以下兩件事：
1. 將任務拆解為 5～7 個「可獨立執行且有明確驗收標準」的原子里程碑（Milestones）。
2. 產出一份可直接存檔的 `PROGRESS.md` 交接看板，包含：【全域不動搖約定】、【里程碑勾選清單 `- [ ]`】、【已拍板決策】與【第一棒執行指令】，方便我後續用「每個步驟開新視窗」的方式接力完成。
